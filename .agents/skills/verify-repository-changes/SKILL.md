# テストと変更後の検証

このリポジトリのテスト方針と、変更後に実行する確認を定める。ブラウザでの確認は既存の Playwright スキルに従う。

## 変更に合うテストを選ぶ

Vitest を使い、対象実装の近くに `*.test.ts` または `*.test.tsx` を置く。例えば `lib/foo/bar.ts` のテストは `lib/foo/bar.test.ts` とする。

| 変更内容 | テストの方針 |
| --- | --- |
| ロジック | 関連テストを追加・更新する。入力値の組み立てや状態遷移などの純粋ロジックは、できるだけ関数単位で確認する |
| ページ・コンポーネント | 画面表示とユーザー操作に対する振る舞いを優先し、props の細かな変換結果だけを確認するテストは避ける |
| ページの `title`・`description`、説明文 | メタ情報や説明文そのものの自動テストは原則不要 |
| 固定値・静的文言 | コードから自明な事項だけを確認するテストは作成しない |

テストケース名には、前提条件と期待結果を書く。「それ以外」のような曖昧な名前は使わない。

## 変更後に検証する

文書だけの変更も含め、次の順序で実行する。

```sh
npm run lint:fix
npm run format:fix
npm run test
```

自動修正後の差分と各コマンドの結果を確認する。失敗や未実施の確認は、成功済みとして報告しない。

Playwright による確認の要否、範囲、実行手順、報告は [plan-playwright-verification](../plan-playwright-verification/SKILL.md) に従う。単体テストの成功だけを理由にブラウザでの確認を省略しない。
