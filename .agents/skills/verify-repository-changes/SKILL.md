# テストと変更後の検証

変更内容に応じてテストを設計し、変更後に検証する。ブラウザでの確認は [plan-playwright-verification](../plan-playwright-verification/SKILL.md) に従う。

## 変更に合うテストを選ぶ

Vitest を使い、テスト対象の実装ファイルの近くに `*.test.ts` または `*.test.tsx` を置く。例えば `lib/foo/bar.ts` のテストは `lib/foo/bar.test.ts` とする。

| 変更内容 | テストの方針 |
| --- | --- |
| ロジック | 関連テストを追加・更新する。入力値の組み立てや状態遷移などの純粋ロジックは、できるだけ関数単位で確認する |
| ページ・コンポーネント | 画面に何が表示され、ユーザーの操作にどう応じるかを優先して確認する。props の細かな変換結果だけを確認するテストは避ける |
| ページの `title`・`description`、説明文 | メタ情報や説明文そのものの自動テストは原則不要 |
| 固定値・静的文言 | コードから自明な事項だけを確認するテストは作成しない |

テストケース名には、前提条件と期待結果を書く。「それ以外」のような曖昧な名前は使わない。

## 変更後に検証する

変更後は次の順序でコマンドを実行する。文書だけを変更した場合も同じ順序で実行する。

```sh
npm run lint:fix
npm run format:fix
npm run test
```

自動修正後の差分と、各コマンドの実行結果を確認する。確認に失敗した項目や未実施の項目は、成功した項目と区別して報告する。

Playwright による確認が必要か、何をどのように確認して報告するかは、上記のスキルに従う。単体テストの成功だけを理由にブラウザでの確認を省略しない。
